Trove for Confluence

Security

Trove runs entirely on Atlassian. There is no server of ours for your content to reach, and every request it makes to Confluence is made as the person using it.

Where the code runs

Trove is a Forge app. Its backend functions execute on Atlassian’s infrastructure, inside Atlassian’s trust boundary. We operate no servers, no database and no third-party services in connection with this app.

No external host is contacted at runtime. There is no analytics service, no telemetry, no error reporting service and no sub-processor. Nothing about your usage reaches us.

The permission model

Every Confluence request is made as the signed-in user. The codebase contains no application-level authentication call anywhere — every one of its Confluence calls is user-scoped.

This makes the central guarantee structural rather than a rule we have to remember to follow. Trove cannot show anyone content their Confluence permissions would not already show them, because it never asks Confluence with any authority other than theirs.

The identity used for any action that writes is taken from the platform context supplied by Forge, never from the browser request. A user cannot act as somebody else by editing what their browser sends.

What is stored, and where

Questions are ordinary Confluence pages. Answers are ordinary Confluence comments. Supporting state — vote counts, which answer is accepted, the per-space index and settings — is kept in Confluence content properties on those same pages.

All of it lives in your Confluence instance, under your space permissions and your retention rules. We hold no copy. If you uninstall Trove, every question and answer stays exactly where it is, still searchable and still exportable, because it was never anywhere else.

Permissions we request

Eight scopes, each tied to a specific product action:

ScopeWhy it is needed
write:pageCreating question pages, the per-space hub page and knowledge articles
read:pageReading questions and their content properties
delete:pageDeleting your own question — Confluence decides who may, and the page goes to the space trash
read:content-detailsFull-text search that reaches answer text, not only titles
read:commentReading answers
write:commentPosting answers and expert mentions
read:spaceResolving which space a question belongs to
read:userShowing people’s names instead of opaque account ids

Every additional scope widens the install prompt for every future customer, so the list is kept to what the product actually does.

AI assistance

AI is off by default and stays off until a space administrator turns it on.

  • Models are hosted by Atlassian. There are no external API keys and your content does not leave the Atlassian platform.
  • The context handed to the model is gathered through the same user-scoped calls as everything else, so the model cannot reach content the person asking could not already open.
  • Answers cite the questions they drew on. Citations are resolved against the numbered context that was actually supplied, so a reference we did not provide simply fails to resolve rather than appearing as a plausible source.

Logging

Trove writes diagnostic entries to the Forge platform log when an operation fails. These stay within Atlassian; they are not forwarded anywhere, and we do not run a log collection service.

Error entries can incidentally contain end-user content. When a Confluence API call fails, the first 300 characters of Confluence’s own error response are included in the diagnostic message, and that response can quote a page title. We declare this rather than claim the logs are content-free, because that claim would not be exactly true.

Reporting a vulnerability

Write to troveappssupport@gmail.com. Please include enough detail to reproduce the issue. Expect an acknowledgement within two business days.

Please report privately and give us a reasonable chance to fix the problem before disclosing it.

What this page does not claim

Stated plainly, so a security review does not have to discover it:

No penetration test has been carried out against this app, and it holds no compliance certification — no SOC 2, no ISO 27001. Rate limiting relies on Atlassian’s platform limits; the app adds none of its own. The per-space index is held in a single content property, which sets a practical ceiling on how many questions one space can hold; the question list is capped at 500 to stay well clear of it, but it is a real limit and would need revisiting for a very large deployment.
